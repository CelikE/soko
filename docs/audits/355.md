# Destructive-workflow fault validation — audit #355

## Outcome and scope

The 13 experiments below passed on macOS 26.6.2 arm64, Git 2.56.0,
Go 1.27.3, and Python 3.15.2 on 2026-10-27. Product source was
`9fa80d9ccdbb9498d8eb4a93116f0783734b9934`; this change adds a harness,
documentation, and CI execution, not a product behavior change. The recorded
audit baseline was older and used a different macOS version.

These results establish the stated predicates, not crash atomicity, full
filesystem fault coverage, or exhaustive Git layout support. Real ENOSPC and
multi-user ownership tests remain **BLOCKED**, as detailed below. No new
concurrency or data-loss defect is asserted.

## Reproduce and obtain complete evidence

From the repository root, using Python 3.9+ and an **unprivileged POSIX user**:

```sh
python3 -m unittest discover -s .github/scripts -p 'test_*.py'
python3 .github/scripts/audit_destructive.py --output /path/to/audit-355.json
```

The second command builds `./cmd/soko` into a disposable directory. To test a
specific source-built executable, pass `--binary /absolute/path/to/soko`.
It never uses the repository's existing `soko` or `cli.test` binaries. Set
`TMPDIR` to a suitable disposable storage location if needed.

Each experiment's JSON record contains:

- Exact subprocess argv, cwd, environment overrides, exit code, stdout, stderr,
  and controller start/completion order. Only the disposable root becomes
  `<fixture>`; SHA values and meaningful output remain intact.
- Before/boundary/after/recovery state: HEAD, refs, index and working-tree
  patches, status including submodules, stash identities, file contents
  including ignored files, and the complete config/journal bytes.
- Injected file writes, permissions and signals; Git-wrapper invocations with
  their real exit/stdout/stderr and whether they reached a barrier.
- PASS/FAIL/BLOCKED classification and the executed recovery/cleanup route.

The opt-in `CI` workflow runs this harness in `Race and coverage (Linux)` and
uploads `audit-355.json` alongside coverage and timings in `linux-race-coverage`,
including when the audit fails. Artifact retention is 14 days; download evidence
that needs longer retention. The report is intentionally generated rather than
checking hundreds of kilobytes of fixture transcripts into the source tree.

Exit 0 means all configured experiments passed, 1 means an experiment failed,
and 2 means a configured experiment could not run on this platform/user.
The separately listed unavailable ENOSPC/multi-user experiments are not counted
as configured experiments or silently promoted to PASS.

## Executed matrix

`soko` below means the disposable source-built binary. Every expected failure
was followed by assertions and recovery, not counted as a pass from exit alone.

| Experiment | Invocation at fault boundary | Control and observed outcome | Recovery verified |
|---|---|---|---|
| `ctx-conflict` | `soko ctx save work --json` | Hold after the checkout ownership ref is pinned. Another **real CLI process** runs `soko alias set canary status`. Release the stale save: exit 1, `saving config: config changed while command was running; retry the command`; empty stdout. | Original staged index, different unstaged contents, and untracked file restored exactly. Concurrent config bytes and older stash survive; new rollback stash retained. |
| `ctx-force-conflict` | `soko ctx save work --json --force` | Same barrier, but an earlier `work` context already exists. Stale forced replacement exits 1 with the same diagnostic and empty stdout. | Original context bytes/stash, unrelated canary stash, new work, and concurrent config update all survive. |
| `ctx-permission` | `soko ctx save work --json` | At the pinned-stash barrier, chmod the isolated config directory to `0500`; a real creation probe confirms `PermissionError`. Exit 1, `saving config: creating temp config file: ... permission denied`; empty stdout. | Old config unchanged; complete index/worktree/untracked rollback and retained stash backups. Restore directory permission before cleanup. |
| `ctx-pin` | `soko ctx save work --json` | Git wrapper returns 73 on the first `update-ref`, after successful stash creation. CLI exits 1, `no repo state could be saved for context "work"`; empty stdout. After inspecting the exact restored work, manually record its completion ref, commit recovered work, and verify switch no longer reapplies the stash. |
| `clean-overlap` | `soko undo` | Hold after recreating A's deleted branch; another process runs `soko clean b --force --json`, appending a new entry. Release: exit 1; stdout reports A recreated; stderr says `updating journal: journal changed; reload before retrying`. | Journal bytes equal the concurrently appended version. Undo B first, retry A (existing branch skipped), verify both exact tips and empty journal. |
| `pull-partial-retry` | `soko undo` | Two recorded pull targets; B has user edits. Exit 1; A reset and checkpointed, B refused dirty and unchanged. | Add new work to A; stash B's blocker; retry resets only B, preserves A's new work and B's backup, and consumes the completed entry. |
| `pull-overlap` | `soko undo` | Hold after A's reset, before checkpoint. Another process cleans C and appends. Release: exit 1, empty stdout, `recording undo progress for a: journal changed; reload before retrying`. | Both entries/preimages survive byte-for-byte; B untouched. Undo C, inspect A's exact pre-tip, back up the journal, manually mark only A completed, retry B while preserving newer work in A. |

Exit 1, empty stdout, `recording undo progress for a: creating temp journal: ... permission denied`. | Previous journal unchanged; B untouched. | `layout-snapshot` | `soko snapshot restore layout --json` | Snapshot taken with a clean initialized submodule; parent advances and module becomes dirty. | `layout-pull` | `soko undo` | Recorded fast-forward with initialized dirty submodule. Exit 1; stdout says `working tree is dirty; commit or stash changes before undoing`; journal remains pending. | Back up module blocker, clean that file, retry; exact parent pre-tip, submodule HEAD and unrelated ignored files preserved. |

Pull entries in these subprocess experiments are **explicitly synthetic**:
the harness makes real commits and writes the supported journal schema, so it
can place barriers precisely in reversal/checkpoint paths without driving a
terminal. Existing `TestPullUndo*` tests also exercise actual local-remote
dashboard pull callbacks. Actual terminal P/u interaction belongs to #356;
this report does not claim to have driven it.

## Safety and synchronization

- All repositories are newly initialized fixtures. Separate HOME, config,
  cache and temp directories; global/system Git config disabled, no inherited
  `GIT_*`/`SOKO_*`/GitHub settings, local file transport only. No network,
  developer-repository mutations, privilege elevation or host disk exhaustion.
- One controller, at most two simultaneous top-level CLI processes. The
  configured `git_path` wrapper runs actual Git and then announces completion of
  one specific operation. File barriers control the overlap; small polling
  sleeps only wait for a known event, never manufacture a probabilistic race.
- 20-second process bounds, 10-second controller waits, 15-second wrapper
  waits; kill/reap the owned process group on timeout or failure. The initial
  Go build has a separate 120-second limit. Fixtures have fixed tiny files and
  a fixed command count, not an unbounded load generator. Child processes also
  have a 1 MiB per-file `RLIMIT_FSIZE`, including captured output, so a runaway
  command cannot fill the host disk with one output file before its timeout.
- Permissions are restored and all temporary repositories removed after every
  run. Evidence is written outside that disposable tree after each experiment.

## Guarantees versus remaining boundaries

**Supported and checked:** cooperative failures before context persistence
attempt index-preserving rollback and retain backup stashes; stale config/journal
updates cannot erase committed concurrent state; normal partial pull undo can
skip durably checkpointed targets on retry; dirty module files block the tested
restore paths; unrelated ignored files survive the tested checkouts/resets.

**Not crash-atomic:** SIGKILL cannot run a deferred rollback. A save interrupted
after stash creation may leave work only in its retained stash. Application or
reset followed by a failed/missing completion checkpoint can require manual
recovery. Do not bypass dirty/HEAD checks, guess numeric stash positions, or
blindly mark an entry completed. Inspect exact refs and file contents, preserve
the journal and backups, stop other writers, and reconcile only verified work.
The harness's manual journal edits happen only in its disposable fixtures after
the competing process exits; they are not a new automatic recovery API.

**BLOCKED — actual ENOSPC/quota exhaustion:** no disposable quota-limited or
size-limited filesystem was provisioned. Permission denial and injected Git
failure are not equivalent to a full disk. Never fill the host volume to test
this. A dedicated bounded filesystem would be required to test write/fsync/
rename failures under genuine exhaustion.

**BLOCKED — multi-user ownership/ACLs:** no second provisioned UID and isolated
ownership sandbox. Tested same-UID POSIX directory denial does not prove other
users' access, ACL semantics, root behavior or network-filesystem guarantees.
The permission scenarios report BLOCKED if the invoking UID bypasses `0500`.

**Not established by this finite matrix:** native Windows permission/signaling
behavior (#357), nested/uninitialized submodules, every submodule-ignore config,
changing gitlink targets, or ignored files colliding with tracked paths in the
target checkout. Ignored files are not context/snapshot backups. The tested
ignored paths are unrelated to tracked target paths; their preservation must
not be generalized to all Git checkout behavior.

Shared prerequisites also have focused Go regressions: exact same-named
tag/branch preimages (#337), missing-base family repair (#340), and incomplete
clean inspection/partial deletion semantics (#348). Run them independently:

```sh
go test -race ./internal/cli -run '^(TestIntegration_UndoRecreatesBranch|TestIntegration_DocFixMissingBaseWithLiveWorktree|TestIntegration_CleanInspectionFailures)$' -count=1
```
